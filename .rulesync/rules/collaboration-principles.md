# Core Collaboration Principles

This document defines the working standards, engineering mindset, and collaboration guidelines between human developers and AI coding agents for the **Parking Management Frontend** project.

## 1. Human in the Loop
- **AI as an Accelerator**: AI tools and agents serve strictly as development accelerators, not autonomous decision makers.
- **Code Accountability**: Human software engineers must thoroughly understand, review, verify, and be capable of explaining every single line of code generated by AI before committing, merging, or opening pull requests.
- **No Blind Acceptance**: AI-generated UI markup, hook implementations, state transformations, and validation schemas must be scrutinized against system invariants, performance constraints, accessibility standards (a11y), and business logic.

## 2. Plan Before Code
- **Structured Design First**: Before writing implementation code or making structural refactorings, formulate a clear step-by-step plan covering:
  - Component hierarchy, props contract, and layout structure (Sidebar, Content, Modals).
  - State management strategy (local component state vs. lifted page state vs. custom hooks).
  - Data flow, client-side validation rules (regex, mandatory fields), and service integration.
  - Responsive behavior across breakpoints (Desktop, Tablet, Mobile).
  - Verification steps (unit tests, manual interaction flows, `npm run build`).
- **Approval Gate**: For major architectural changes, restructuring the 4-layer architecture, or large dependency modifications, present the plan for review before making irreversible edits.

## 3. DRY and Clean Architecture
- **Don't Repeat Yourself (DRY)**: Eliminate duplicate logic across components and pages. Shared validation rules, formatting helpers (dates, phone numbers), and pagination logic must live in a single source of truth (`src/features/` or utility modules).
- **Thin Presentational Components**: Keep UI components minimal and focused solely on rendering and emitting events (`onSearch`, `onEdit`, `onDelete`). Components should not contain raw business logic or direct mock API calls.
- **Decoupled Business & Service Layer**: Encapsulate domain logic, data transformations, and state mutations within feature services (`src/features/contacts/contactsService.js`) or specialized custom hooks.

## 4. Senior Engineer Mindset
- **Production-Grade Quality**: All code must meet industry standards for readability, maintainability, high UI fidelity, clean component boundaries, and defensive design.
- **Real Verification**: Never assume an implementation works without running live verification (checking browser console for React key warnings, testing edge cases like empty lists or long text, and executing `npm run build`).
- **Proactive Risk Mitigation**: Anticipate race conditions (rapid search typing), state synchronization bugs, stale closures in `useEffect`, layout overflow on mobile screens, and memory leaks.
